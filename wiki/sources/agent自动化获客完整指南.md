# 来源摘要：如何使用 Agent 自动化获客（完整指南）

## 摘要

原文作者 [[chris-everest|Chris Everest]]（增长与自动化方向独立作者）的完整操作指南（中文版由 @yibie 转译）。核心方法一句话：**"找到已经在付钱的人，把他们的数据抓下来，做出能触达他们的东西，然后放到他们看得见的地方。"** 全文围绕三条可由 Agent 自动运行的线索管道（pipeline）展开：① 数字产品线索（买家画像 → whop ads 投放）；② 本地实体线索（公开数据找问题物业 → 渲染修复效果 → 触达业主）；③ 把线索卖给本地企业。所有流程打包成一个 [[skill文件|Skill 文件]]，由 [[grok-bot|grok bot]] 或 [[hermes]] 执行。

> **合规提示（原文自带声明）**：文中的冷启动短信/邮件触达与平台数据抓取，**在部分地区法规和平台规则下有限制**，落地前请自行确认。

## 核心内容

### 1. 通用机制：Skill 文件 + 两个 Agent

- **[[skill文件|Skill 文件]]是核心**：用 [[claude-code|Claude]] 把整套流程写成一个 skill 文件（规则在最上面，步骤在下面），连同 API key 和工具权限交给 agent，它读了就能跑。写一次，任何读到它的 agent 都能跑。
- **agent 二选一**：
  - [[grok-bot|grok bot]]：上手简单，自带一台电脑（终端、浏览器、文件系统），像聊天一样交互，零配置；
  - [[hermes]]：起步更技术化，但为**计划任务**而建——用 Claude 的一段 prompt + hermes 文档 + Telegram bot token（来自 @BotFather），部署到 Railway，之后所有 prompt 通过 Telegram 发送，跑起来更省心。

### 2. Pipeline 一：数字线索（给有产品的人）

| 步骤 | 做法 |
| --- | --- |
| ① 从产品推买家 | 第一段 prompt 是产品，回来的是买家的人口学身份 + 心理画像（如"试过好几种办法、为没一个成功而沮丧的 34 岁男性"），以及他们在网上的具体聚集地（subreddit、Facebook 群组、YouTube 频道等，要实际名字） |
| ② 抓三个月数据 | 通过 [[apify|Apify]] MCP 对每个"有买家"的地方抓帖子、评论、原话，保留来源 URL、日期、互动量；出现超过三次的问题/抱怨用**他们自己的原话**记录并附次数 |
| ③ 创意计划 | 取出现次数最高的 3 个抱怨/欲望做成 3 个 angle，每个 angle 用画像原话写 3 个 hook（共 9 个素材）；素材显示"他们想要的结果"而非产品；素材不足的 angle 直接砍掉 |
| ④ 投 [[whop|whop ads]] | 跑在 whop 的 Meta 代理账号上（投 Facebook / Instagram）；pixel 内置于 whop 页面、用真实支付数据归因；1 个 campaign × 3 个 ad set × 3 素材；**每单成本连续三天高于产品价格即暂停** |
| ⑤ 收集线索 | 广告把人送到自己的页面；whop 告知谁访问过、谁到过结账，agent 对点了没买的人跟进 |

- 素材生成：agent 通过 replicate 或 fal 调用，作者称当时"gpt image 2.5 是最好的图像模型，seedance 2.5 是最好的视频模型"（作者个人判断）。
- 投放资金当天可从 whop 待结算余额出——"广告带来买家，买家养广告"；用 whop ads 本身免费，只付投放花费。

### 3. Pipeline 二：实体线索（给本地生意）

| 步骤 | 做法 |
| --- | --- |
| ① 选行业 | 选"一个词能说清、物业或商铺本身就能看出需求"的行业（太阳能、屋顶、园林、泳池、招牌等）；**不是创造需求，而是发现需求** |
| ② 找数据源 | 第一段 prompt 是行业，回来的是"哪个公开数据源能显示出它"（卫星影像、街景、挂牌照片、商户信息、许可记录、房产记录）；**只用一个数据源、一个判定条件**——每加一个过滤条件就砍短名单、加进一个猜测 |
| ③ 建候选名单 | 从房产记录/商户信息拉地址 → 先跑免费的影像元数据检查（存在与否、多旧），只对"较新"的付费 → 通过判定的拉渲染参考图；边界情况标 review 不判进或出 |
| ④ 渲染修复效果 | 图像模型把修复效果做到**真实的物业**上；必须是**编辑**（只改要修的那一个东西）；需要 3–4 帧参考图（只有一张图，图外的一切只能靠猜） |
| ⑤ 触达业主 | 三渠道：邮件、短信、明信片（渲染图一样、都指向专为该物业建的页面：渲染图 + 询问报价时间的表单）；**作者称其实测中明信片效果远好于邮件和短信**（个人测试）；有地址就寄信、有邮箱/电话就加邮件/短信 |
| ⑥ 接住回应 | 扫码、填表、回复就是线索（带地址、业主名、报价时间、渲染图）；打开未填表的人也记录，第二批跟进 |

### 4. Pipeline 三：把线索卖出去（给没有产品也没有生意的人）

- **找企业**：Google Places 拉出目标城市里评论数 15–200、老板亲自经营（非加盟）的公司，记下每家覆盖区域。
- **触达**：不用推销——消息里带一批**已生成好的、就在他们区域里的线索样本**（3 个线索做一页 PDF），老板的问题会从"这玩意行不行"变成"这样的还有多少"；至少跟进两次（老板通常不回第一条）。
- **定价**：第一个月**按条收费**（对照该行业平均客单价）；第二个月**按月托管**（一组 zip code 内独家，agent 只为这一家继续跑）。
- **交付**：线索落在看板上（地址、业主、渲染图、表单填写、时间戳、状态）；"让他们持续付钱的东西是：看板在他们什么都不用做的情况下自己满起来，以及从里面成交的第一单。"

### 5. 人机分工

Agent 负责：寻找、读取、画像、素材、物业扫描、渲染、建页面、外联批次、表格、每日报告。**留给人的三件事**：

1. 渲染图在批次发出前人工检查；
2. 与商家老板的第一次对话；
3. 任何广告的预算（agent 提建议，人拍板）。

### 6. 什么会崩

- **公开影像过期**：agent 读到的可能是三年前的图，问题早被修好；新区域第一批就是发现影像多旧的地方，"信之前先看几张"。
- **whop ads 拒收承诺性素材**：不能编收入数字、不能用假证言、不能暗示买家会得到某种结果；合规检查在投之前跑，一条被拒会拖累整个广告组。
- **老板不回第一条消息**：会回第二条或一周后的跟进，建议至少跟进两次。

### 7. 运行纪律（skill 文件的规则层）

- 一个行业或一个细分一张表，绝不跨表读；
- 任何会接触真人或花钱的动作，先停下来问；
- 不确定的东西标成 review，不要猜；
- 素材不够就砍掉并说明原因，不要硬凑。
