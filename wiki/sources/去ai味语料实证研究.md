# 来源摘要：做了一个可能有最多数据支撑的去 AI 味 skill

## 摘要

作者（X：[@Zhiyu333](https://x.com/Zhiyu333)）用**语言学对照实验**的方法做了一个去 AI 味 skill：收集 **329 篇人类文章（164.8 万字）** 与 **5 个模型各 60 篇共 300 篇 AI 文章**，合计 **629 篇 / 283 万字**，对 **26 项候选特征**逐项计算频率差异，最终 **11 项通过检验**。项目已开源：`https://github.com/larashero3-dotcom/lieflat-less-ai-tone`。

这篇文章对本库的意义在于：它给 [[ai写作去味]] 主题提供了**第三种立场**——既不是"用一堆 Skill 改稿"（Skill 组合派），也不是"拿真实样本喂模型"（真实样本派），而是**先用量化方法验证"AI 味到底是什么"**，再据此写规则。作者最反直觉的结论是：**流行认知里的大量"AI 味特征"经实测并不显著**，按那些直觉去改，可能让文章离人类写法更远。

> ✅ **已核实（2026-09-15 网络检索 + 读取仓库 README 与 SKILL.md 原文）**：**本页全部统计数字与仓库 README 完全一致**；**规则集（SKILL.md）与统计结论自洽**——被证否的特征不仅未进入改写清单，还被单列为"**不作为改写理由**"的硬约束。仓库为 `larashero3-dotcom/lieflat-less-ai-tone`，**MIT，780★ / 56 forks**，创建 2026-08-20。

## 核心内容

### 1. 问题起点（作者的动机）

作者自述对 AI 输出产生了"近乎生理性的厌恶"（如"不是 A 而是 B"对举结构、破折号滥用），并指出既有两个结构性缺陷：

1. **覆盖不全**：很多 AI 味"能感觉到但规则里没写"；
2. **误伤**：有些规则把作者自己的表达习惯也一并消灭了。

根源是——多数开源项目**来自个案观察与语感总结，没有被系统检验过**。

### 2. 语料与研究设计

| 维度 | 内容 |
| --- | --- |
| 人类语料 | **329 篇，164.8 万字** |
| AI 语料 | **5 个模型 × 60 篇 = 300 篇** |
| 合计 | **629 篇，283 万字** |
| 参与模型 | **Claude Opus 4.6、DeepSeek V4-Pro、Gemini 3.1 Pro、GPT 5.6 Sol、Kimi K3** |
| 生成条件 | 与人类语料**同话题同体裁**；**不联网、不给任何风格指令**，只提供话题；同一 Agent 环境 |
| 语料语言 | 主要是**中文** |
| 候选特征 | **26 项**（初测）→ **11 项显著** |

**显著性阈值**：

- **≥ 2.0×**（AI 频率 ÷ 人类频率）→ 判定为显著的 AI 味特征；
- **0.8 – 1.25×** → 视为无差异；
- **< 0.8** → 人类用得更多，按此方向改写只会更不像人写的。

**额外统计约束**（作者列出）：

- 人类侧各组数值不能相差 **5 倍以上**（排除体裁偏差）；
- 特征必须落实到**可定位的句段和词形**（排除依赖语义理解的判断）。

**规模教训**：作者最初只用 2 个模型的 30 篇样本，得出"破折号是 Claude 独有特征"；扩到 300 篇后发现 **DeepSeek 破折号频率比 Claude 更高**（每千字 5.16 vs 4.25），GPT 几乎不用（0.11）。→ **样本不足会把单一模型的个体倾向误读为 AI 共性。**

### 3. 通过检验的 11 项显著特征

作者指出：真正通过的 11 项**集中在篇章和结构层面，词汇和标点上反倒没那么明显**。

| 特征 | 倍数 | 说明 |
| --- | --- | --- |
| **段首零回指评论** | **4.4×** | 段与段之间缺少衔接，新段落开头直接抛出评价（"听起来像一条功能描述"）却不交代评价对象 |
| **拟人化喻体** | **7.3×** | "像一位不知疲倦的助手"这一类 |
| **冒号空转句** | **9.4×** | 专门用来引出列表的冒号，如"主要有以下几种场景："——句子本身不带信息 |
| **提示语冒号** | **3.8×** | "核心是：""说白了："这类说法 |
| **数字密度** | **0.35×（方向相反）** | AI 用数据比人类**少**——所以不能反过来让它"补数据"，而是**尽可能翔实的数据支撑能让文章不那么 AI 味** |

**关键反直觉点（作者详述）**：

- **段首衔接词总量两侧其实没差别**（AI 14.4%，人类 15.1%）——差异只出在评论句**省掉了回指成分**。修法：补一个"这"或其他指代词。
- **比喻句总数 AI 反而低于人类**——AI 的比喻问题**出在不够贴切，跟数量没关系**。细分后发现是**拟人化**这一类显著偏高。作者推测原因：模型并不真的理解比喻，不知道什么像什么，只是把看上去相关的东西硬凑到一起。
- **冒号总量差异不显著**，但"空转句"和"提示语"两个细分用法显著——**说明特征定义必须足够清晰**。

### 4. 翻译腔：18 种候选，只有 5 种通过

作者称 Moxt 帮他列了 **18 种翻译腔特征**，实测只有 **5 种**通过检验：

1. 过长的前置定语
2. "当……时"从句
3. 前置的话题壳
4. 句首连接词
5. "这意味着"式的复述句

剩下 **13 种频率太低**——"确实是翻译腔，但数据不支持它们是 AI 痕迹"。

### 5. 未通过验证的特征（最具争议的部分）

| 特征 | 实测结果 | 流行认知 |
| --- | --- | --- |
| **正文设问句** | **人类是 AI 的 17 倍**（人类 1.83/千字，AI 0.10）；5 个模型都不爱用设问句 | "AI 爱设问"几乎是所有去 AI 味建议的标配——**按"减少设问"改，只会离人类更远** |
| **句长均匀度** | 修正切句 bug 后 **比值 0.87，两侧无差异** | 最初显示"AI 句长变异系数是人类的 **51 倍**"，是全表最强特征，作者一度排在规则第一条 |

**"51 倍"的 bug 详情**（重要教训）：切句程序出错——**Markdown 表格和没有句号的长列表被当成了一整个句子**，某一组甚至冒出一个 **19,335 字的"段落"**。修正后差异消失。

**检验本身的准确性也有问题**：作者指出很多 AI 使用的问句实际上并不是严格的设问句，所以在检验时会被遗漏。"如何界定检验标准，是个很需要研究的问题。"

### 6. 不同模型的 AI 味表现差异极大（核心发现）

作者结论：**可能根本不存在统一的"AI 文风"**。同一特征，模型与模型之间能差到 **40 倍**。

| 特征 | 最高 | 最低 |
| --- | --- | --- |
| **破折号** | DeepSeek V4-Pro **5.16**/千字 | GPT **0.11**/千字（≈**40×**） |
| **对举结构** | GPT 5.6 Sol **1.26**/千字 | Gemini 3.1 Pro **0.29**/千字 |
| **提示性冒号** | DeepSeek 0.43、Claude 0.38 | GPT、Gemini 都偏低 |
| **问句小标题** | Gemini **0.173**/千字（一骑绝尘） | **Kimi 为零** |

→ 拿单一模型总结出来的"AI 特征"，换个模型就未必成立。

### 7. 作者自述的不足与未来方向

**已踩的坑（操作规程教训）**：

- **同一个问题栽过六次**：正则表达式实际覆盖范围比想定义的规则更宽，跑出来的是**假数据**。
- **问句小标题的分母错误**：Agent 一开始拿"每千字"当分母，算出 32 倍。但 **AI 平均每篇有 10 个小标题，人类只有 1–2 个**，小标题总量本身就差 5–10 倍。换成**占小标题总数的比例**后，AI 2.7%、人类最高一组 3.6%，**差异就消失了**。
- **确定下来的操作规程**：**改规则之前，先抽样看 20 条命中，再看频率。**

**方法论层面的局限（作者自评）**：

1. **280 万字远远不够**："280 万字无法代表'AI'，就像 280 万字也无法代表人类的写作"。
2. **应针对具体体裁做专门 skill**：小说、学术论文、普通自媒体对"AI 味"的容忍度和表现形式完全不同。本项目可以理解为**针对媒体/自媒体深度文章**的场景。
3. **329 篇人类文章在"人类写作"这个大集合里还是太少了**——光破折号一项，**来源与来源之间就能差出一百倍**，语料再扩很可能改掉部分现结论。
4. **写作本身太主观、太依赖智力特征，量化难度极高**：prompt 或 skill 优化只能解决局部问题——"能让它不用破折号，但很难让它明白一个比喻到底什么时候才算贴切"。

**最终判断（作者的核心结论）**：

> 去"AI 味"乃至 AI 写作这一整个能力，**可能是更需要在模型预训练阶段解决的问题**。作者认为自己的工作"某些方面更像是预训练阶段的工作，只是样本量太微不足道了"。
