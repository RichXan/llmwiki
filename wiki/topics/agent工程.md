# Agent 工程

## 摘要

「Agent 工程」关注**单个 Agent 会话的技术实现**：系统提示与上下文如何组织、工具调用如何往返、上下文如何被压缩、记忆如何跨会话延续。它以 [[claude-code|Claude Code]] 为当前主要样本，核心问题是：**在上下文窗口已做到 1M 的时代，为什么仍然需要上下文管理？** 答案在于两条底层机制——[[kv-cache|KV Cache]] 与 [[注意力机制]]。

### 核心结论

- **上下文管理只做两件事**：顺应 KV Cache 前缀缓存以降成本；裁剪组织上下文以解决注意力问题。详见 [[上下文管理]]。
- **单向追加是默认纪律**：只有保证老内容不动、新内容垫后，才能最大化命中前缀缓存。
- **传统四方案都有代价**：摆烂报错、滑动窗口、摘要压缩、外挂 RAG，共同问题是"要么丢细节，要么牺牲速度与成本"。详见 [[上下文压缩]]。
- **上下文管理 ≠ 记忆**：它只是在窗口内"拆东墙补西墙"，跨会话的长期记忆才是下一步。详见 [[长期记忆]]。
