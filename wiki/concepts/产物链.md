# 概念：产物链（Artifact Chain）

## 摘要

**产物链** 是 AI 原生 SDLC 的核心机制之一：**每个阶段向版本控制提交一个产物，下一个阶段从读取这个产物开始**。这条提交链本身构成**审计轨迹**，能回答"谁提了什么要求、agent 做了什么、谁批准的"。来源见 [[从intent到闭环-ai原生sdlc]]。

## 核心内容

### 各阶段产物一览

| 阶段 | 产物 | 下一阶段的触发条件 |
| --- | --- | --- |
| Plan | [[意图文件\|intent.md]] | 产品负责人接受 |
| Design | `spec.md` | 产品负责人批准 |
| Build | `plan.md`、diff、测试 | 工程师接受计划 |
| Test | 测试输出、CI check run | 检查通过 |
| Deploy | 带评审记录的 PR | code owner 批准合并 |
| Maintain | 事故记录 → 新的 intent.md | 控制带被突破 |

### 为什么早期用 Markdown、后期用代码

- **早期阶段（Plan/Design）用 Markdown**：因为产品负责人和 agent 都能读、都能改同一个文件。
- **从构建阶段往后**：产物就是代码和它的记录。
- **审计价值**：提交链记录了要求、行动与批准三者的对应关系，是 AI 原生 SDLC 回答"问责/审计"问题的基础。

### 与"门"的关系

产物被**接受**就触发下一道 [[审批门]]；设计评审因此发生在代码生成之前，那时改方向只需改文档。

### 度量思路

几乎所有的领先/滞后指标都从 **git 时间戳、PR 元数据、CI 日志、OpenTelemetry、事故追踪器** 里获取，不新建度量体系——例如"intent 与 spec 两次提交的时间差"可直接由 git log 得到。
