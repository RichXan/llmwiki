# 概念：Harness 极简主义

## 摘要

**Harness 极简主义**主张 coding agent 的**外层框架（harness）应尽可能小**：只提供最基础的工具与极短的系统提示，把能力增长交给**按需加载**与 **agent 自我扩展**，而不是把功能预先堆进框架。它出自 [[armin-ronacher|Armin Ronacher]]（见 [[armin-ronacher-九条反直觉判断]]），在 [[pi-agent|Pi]] 上是最激进的实践。

## 核心内容

### 立论：竞争在收敛到「基础功」

- 来源判断："所有 harness 的竞争都在收敛到「基础功」，因为**模型自己越来越会用电脑**。"
- 推理链条：模型越会用电脑 → 框架越不必预先封装能力 → 最省的形态就是**给它一个 shell（bash）**。
- **反直觉之处**：bash 管道是**最省上下文**的形态——工具描述与参数 schema 都要占用每一轮的 token，而一个通用 shell 只需一段短说明。这也解释了为什么"工具看似繁多"的 [[codex|Codex]] **底层仍在大量调用 bash**（来源观察）。

### 与 Pi 的实现对应

| 主张 | Pi 的实现 |
| --- | --- |
| 只给基础工具 | 默认四个工具：read / write / edit / bash |
| 系统提示极短 | 系统提示 + 工具定义合计 **< 1,000 tokens**（对比其他 harness 常达 7,000–10,000） |
| 能力按需加载 | **lazy skills（渐进披露）**：每个 skill 每轮只贡献一行描述，真正调用时才加载完整内容 |
| 能力靠自我扩展 | 让 agent 自己写 TypeScript 扩展，即时生效、无需重启 |

### 与既有路线的分歧（并列保留，不取舍）

| 维度 | 极简派（Ronacher / Pi） | 全功能派（如 [[claude-code|Claude Code]]） |
| --- | --- | --- |
| 系统提示规模 | < 1,000 tokens | 约 7,000–10,000 tokens（第三方口径） |
| 能力来源 | 用户/agent 自己按需扩展 | 官方预置（sub-agents、hooks、MCP、plan mode） |
| 上下文开销 | 按需付费（渐进披露） | 恒定税（预加载），但开箱即用 |
| 安全护栏 | **无内置沙箱**，需自建容器/VM | 有权限机制与审批门 |
| 上手成本 | 高（需自行组装） | 低 |

> 关键分歧点：**上下文开销是"恒定税"还是"按需付费"**。极简派认为预置功能是一场"token 税"，全功能派认为开箱即用换来更低的使用门槛与更完整的护栏。两种路线**各有代价**，本库并列保留。

### 与 [[上下文管理]] 的关系（重要对照）

- 本库既有的 [[agent工程解析-上下文管理|@coder_left 的《Agent 工程解析》]]深入 [[claude-code|Claude Code]] 的内部机制，讨论如何在上下文膨胀后**压缩、裁剪、外挂记忆**。
- Ronacher 的路线是**从源头避免问题**：如果框架本身不预置大量工具与提示，就不必频繁压缩。
- **两者的共识**是"上下文是稀缺资源"；**分歧**在解法——**事后治理 vs 事前极简**。这是本库目前记录的第一组明确的 agent 工程路线对立，并列保留。
