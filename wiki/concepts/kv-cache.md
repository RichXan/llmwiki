# 概念：KV Cache

## 摘要

**KV Cache** 是大模型推理时"用空间换时间"的缓存机制：生成内容是单向逐字进行的，正常情况下每算一个新 token，前面所有 token 都要重新参与计算；为避免重复推理，把前面算好的中间状态缓存下来，即 KV Cache。它是 [[上下文管理]] 降低成本这条主线的底层依据。来源见 [[agent工程解析-上下文管理]]。

## 核心内容

### 成本意义

- 命中缓存的价格通常是非命中缓存价格的 **1/10，甚至 1/50**，非常便宜。
- 因此上下文管理的一个核心目标就是**最大化缓存命中率**。

### 一条物理规则

> **必须保证最前面的前缀绝对一致。**

只要在上下文中部改动一个字、或插入一条消息，**从改动位置往后所有缓存全部失效**，只能重新计算。

### 对工程实现的三点约束

1. **单向追加**：Agent 开发中消息绝大多数只追加到末尾，保证老内容纹丝不动。
2. **静态前置、易变垫后**：把长年不变的系统人设、工具协议焊死在头部，把高频变动的对话垫在最后——不管聊多少轮，最前面的两三万 Token 永远吃满缓存折扣。
3. **规则文件的排序**：企业托管策略与全局用户偏好（几乎不变）放最前，项目规范、`CLAUDE.local.md`、子目录规则（高频改动）垫后，改动只破坏尾部缓存。详见 [[上下文管理]]。

### 与其他机制的联系

- `CLAUDE.md` 的五类形态之所以按"系统托管 → 用户全局 → 项目共享 → 本地覆盖 → 子目录"排序，核心目的就是配合 KV Cache。详见 [[claude-code]]。
- 缓存有生命周期（Anthropic 一般为 **5 分钟**，部分高权限组织可达 **1 小时**）；[[上下文压缩]] 中的 TimeBasedMicrocompact 正是利用"闲置超期后缓存本已失效"这一点来安全清理。
