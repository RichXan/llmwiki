# 概念：视觉自愈循环

## 摘要

**视觉自愈循环** 指让模型自己"看"渲染结果、自己诊断、自己改代码的一类 UI 工作流：把 **渲染 → 1:1 截图 → 逐像素比对生成 Diff → 先写诊断再改代码 → 保留历史最佳** 串成闭环。它主要用在 Screenshot-to-Code（把截图复刻成页面）等场景，源头见 [[ai改ui翻车]]。

## 核心内容

### 工作流

```text
目标截图 ──▶ 模型写 HTML ──▶ 浏览器 1:1 渲染截图 ──▶ 逐像素比对生成 Diff
                                                         │
保留历史最佳 ◀── 重新渲染 ◀── 模型先写诊断再改代码 ◀── 原图 + 渲染图 + Diff
```

### 两个关键设计

1. **先诊断再改代码**：每次修改前，要求模型先回答三个问题——① 最大的问题在哪里；② 可能是哪个元素、哪个 CSS 属性造成的；③ 准备怎么改。说完才动代码。
   - 附带价值：即使不开自动改，这段诊断也能当**检查清单**用。
2. **保留历史最佳，而非取最后一轮**：因为"同一套流程不一定每一轮都比上一轮好"。明显问题通常前一两轮修掉，之后全是细节，"改一处很容易又碰坏另一处"。实测中亮黄卡片第二轮更接近、第三轮却回落，最终保留第二轮版本。

### 三个坑（反馈流程本身的错误）

| 坑 | 现象 | 后果 |
| --- | --- | --- |
| **尺寸不一致** | 目标图被缩放过，浏览器又用另一个尺寸截图 | 两图从未对齐，**整体偏几像素就炸出一大片误差**，连"标准答案"放进去 Diff 都一大片 |
| **动画未播完** | 截图时淡入动画还没结束，内容仍透明 | 去掉动画后肉眼正常，自动比对反而**更差**——透明时露出背景，像素算法觉得"更像" |
| **在坏版本上叠加** | 这一轮已改坏，仍继续打补丁 | 错误层层叠加，"在歪掉的地基上继续盖楼" |

### 三条规则（来源的最终结论）

1. 原图与浏览器截图使用**同一尺寸**，不再二次缩放；
2. 固定**视口、字体、动画状态和截图时机**；
3. 每轮从**历史最佳版本**继续，不在变差的代码上叠补丁。

### 核心论断

> **Diff 只是工具，不是裁判。** 如果反馈本身是错的，模型不会替我发现这件事，它只会拿着这份反馈非常认真地修错方向。

配套的克制态度：**不默认"轮数越多越好"**——先把明显问题修掉，后面不再变好就停。

### 与其他概念的呼应

- 该闭环与 [[ai原生sdlc]] 中 Test 阶段的"给 Agent 反馈回路"同源：那里提出"UI 工作用截图闭合循环，两到三轮是正常的"，本文则是这套思路在实操中的踩坑记录与修正。
