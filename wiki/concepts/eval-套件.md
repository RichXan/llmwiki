# 概念：eval 套件

## 摘要

在 AI 原生 SDLC 中，**eval 套件**被称作"阶段门 QA 的 AI 原生对应物"：用一组真实的、可接受结果已知的任务，对 Agent 的**配置**（模型、prompt、`CLAUDE.md`、skill、hook）做回归测试。核心论据是：**这些配置在引导 Agent，应该得到和代码一样的回归测试**。来源见 [[从intent到闭环-ai原生sdlc]]。

## 核心内容

### 运行时机

eval 在 **Agent 配置变化时运行**——换模型、改 prompt、改 `CLAUDE.md`、改 skill、改 hook 都算；同时也做定时运行。

### 建设步骤（来源给出的做法）

1. 从近期工作里收集 **20 到 50 个真实任务**和可接受的结果；
2. 写成 prompt + 检查项（测试通过、lint 干净、行为不变、策略遵守）；
3. 定时运行，并在配置变更时运行；
4. **用通过率把关配置变更的合并**；
5. **每个生产事故都变成一个 eval** 留在套件里。

### 维护成本与寿命

- 作者指出 eval 套件是**活的**：模型进步之后有些用例会失去区分度，需要不断补充。
- 局限（解读作者补充）：20–50 个 eval、每次配置变更都跑、每个事故都加，**API 消耗与维护精力都不小**，原文只提到需要一个有预算的 API key，维护成本可能被低估。

### 与其他概念的关系

- eval 是 [[建议性控制与确定性控制]] 之外、作用于**配置回归**的另一道保障。
- 与 [[产物链]] 的度量思路一致：指标尽量来自已有系统（这里的"结果"来自真实任务与 CI）。
