# 概念：意图文件（intent.md）

## 摘要

**意图文件（intent.md）** 是 AI 原生 SDLC 中计划阶段的产物，也是整条 [[产物链]] 的起点。它由发起人**用自己的话**写出想要什么、为什么，替代传统流程中经过 backlog、user story、故事点、refinement 会议层层传递的"二手需求"。

## 核心内容

### 内容结构

- 想要什么、为什么；
- 有哪些约束；
- 影响哪些用户和系统；
- 还有哪些没想清楚的问题。

### 实施细节（来自来源）

- **谁来写**：发起人直接和 Claude 讨论后写出，而非由分析师生成。
- **如何提交**：非工程师通过 claude.ai 或 Cowork 使用 Claude，**不需要会 git**，由 GitHub connector 代为提交。
- **放哪里**：单个产品最简单的做法是在产品仓库里放一个 `intent/` 目录，让意图文件与派生代码相邻；单独的 intent 仓库只在意图跨多个仓库时才划得来。
- **模板即 skill**：模板可以写成 [[建议性控制与确定性控制|skill]]，由技术人员搭建、负责人签字。
- **接受记录**：产品负责人审阅并修正 agent 写的 intent.md 后提交，接受/拒绝以 merge 或关闭 review 的形式留下记录。

### 度量

- **领先指标**：从第一次对话到 intent.md 提交的时间（作者预期从几周降到几小时）。
- **滞后指标**：被产品负责人接受、进入设计阶段的比例；以及 spec.md 第一次提交之后 intent.md 又被修改了几次（用于观察意图是否稳定）。

### 与下游产物的关系

- `intent.md`（Plan）→ `spec.md`（Design）→ `plan.md`（Build）。详见 [[产物链]]。
- 在维护（Maintain）阶段，事故诊断也会被写成 intent 格式，重新回到计划阶段——这是"流程从线性变循环"的具体体现。
