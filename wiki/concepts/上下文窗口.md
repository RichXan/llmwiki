# 概念：上下文窗口

## 摘要

**上下文窗口（Context Window）** 是大模型的**短期记忆载体**：动态驻留在当前会话中的信息，类似"两人当面聊天时摆在桌上的便签纸"。它与会话强绑定——新开会话、手动清空、或内容被挤出窗口，模型就"当场失忆"。它是理解 [[上下文管理]] 的前提。来源见 [[agent工程解析-上下文管理]]。

## 核心内容

### 两种记忆的对照

| | 长期记忆（权重参数） | 短期记忆（上下文窗口） |
| --- | --- | --- |
| 形成 | 预训练/微调阶段固化 | 会话中动态驻留 |
| 更新 | 日常聊天无法实时更新 | 每轮对话实时追加 |
| 范围 | 跨会话稳定生效 | 仅当前会话 |
| 类比 | 多年读书积累的通识与语言本能 | 桌上随时可换的便签纸 |

### 1M 窗口时代的老问题

- 来源提出的问题：OpenAI 与 Anthropic 相继把窗口做到 **1M**，是否意味着"上下文管理时代结束"？
- 结论是**没有结束**：窗口变大只解决了"装不下"，没解决**成本**（KV Cache）与**注意力**（聚光灯分散）问题。详见 [[上下文管理]]、[[注意力机制]]、[[kv-cache]]。
- 常见误解：以为给到 200K 模型就能"全部看懂"——实际注意力更像聚光灯，内容越多越分散。

### 与会话循环的关系

上下文窗口里的内容随 [[agent-loop]] 单向追加：用户消息、assistant 回复、`tool_use` 与 `tool_result` 依次堆叠，直到触发 [[上下文压缩]]。

### 与长期记忆的差距

窗口是"短期草稿"，关掉终端或 `/clear` 即清空；要让 Agent 在会话关闭后仍记得进展与偏好，需要跨会话的 [[长期记忆]]。
