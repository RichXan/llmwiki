# 概念：可内省性（Agent 的可查看与可问责）

## 摘要

**可内省性**指的是：人能**亲眼看到 agent 到底做了什么、哪里没搞懂**，而不是只能去问一个"可能撒谎的 agent"。它出自 [[armin-ronacher|Armin Ronacher]]（见 [[armin-ronacher-九条反直觉判断]]），被他视为编码 agent 的**刚需**，并从两个层面论证：**社会问责**（机器不可问责）与**工程可读**（人看得懂才改得动）。

## 核心内容

### 论证一：机器不可问责，所以人类不会退场

> 「你得能怪到某个人头上，**机器不可问责**——社会不会这么运转。」

- 推论：**银行不会 vibe code**。凡涉及后果归属、合规、责任的场景，人类必须留在链条里。
- 这也解释了为什么 Ronacher 主张**有意保留工程摩擦**（intentional engineering friction）：数据库迁移、权限、依赖、可靠性、架构等环节**必须有人类判断**，而非全自动通过。
- 相关风险（其在 AI Engineer 会议的表述）：**巨大的 PR 会淹没审查流程，同时悄悄累积技术债**——代码产量倍增，但"对生产事故负责的人"没有倍增。

### 论证二：可读的产物形态胜出

> 这也是 **Markdown、JSON、Unix 管道在赢**的原因：**人能看懂**。

- 判据不是"机器处理起来多高效"，而是**人能不能直接审视**。
- 与本库 [[harness-极简主义]] 同源：偏好文件、shell 命令、测试、直接编辑这类**人可检查**的形态，反对不透明的抽象与配置。

### 落地要求（据其会议档与工程实践）

| 层面 | 要求 |
| --- | --- |
| **代码库** | 显式组件边界、集中式 SQL 访问、可复用接口原语、**独特函数名**、禁止隐藏失败的 lint 规则 |
| **流程** | 自动化只做**机械性修正**；架构/权限/迁移等保留人类强制判断 |
| **工具** | harness 需让"进入模型上下文的内容"完全可见，不背着你注入上下文 |
| **审查** | 审查可从干净上下文开始，先标出新引入的依赖等细节，再交人查看 |

### 与既有概念的呼应

- 与 [[ai原生sdlc|AI 原生 SDLC]] 的 [[审批门]] 同构：都是"自动化执行 + 人类在关键点拍板"，但 Ronacher 的表述更强调**问责归属**这一社会性理由，而非单纯的风险控制。
- 与 [[ai原生sdlc]] 的 [[建议性控制与确定性控制]] 互补：确定性控制解决"能不能拦住"，可内省性解决"人是否理解发生了什么"。
- 与 [[ai创业与需求发现]] 中"技术不再稀缺、判断力稀缺"的论述方向一致：人的价值上移到**判断与问责**。
